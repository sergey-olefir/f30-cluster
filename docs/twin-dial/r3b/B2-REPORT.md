# B2 - live tabs and the tab bar (Twin Dial 0.1.1 build)

Branch `twin-b/b2` (worktree `.claude/worktrees/b3-b2`). No push, no version bump, no change to `apps/f30_cluster` or `apps/driver_profiles`.

## What was built
1. **`shared/twin_tabs.js`** (new, ported from `twin-r3/sb`; the probe files and `probe-p13.json` were not taken). Tab state, the rules of SPEC-R3 3.4 as a level machine with driver overrides: (1) a message -> tab 2 at any speed, never locked; (2) a call -> tab 4, built and **off** (`config.tabs.callSelects`, reads `hud.td.callState`); (3) guidance -> tab 5; (4) the driver's last choice. Rules 2-4 and the return to the choice wait above the lock speed; the message's own end returns to the tab before it. The driver may **leave tab 2 during a message** (key or setting; B3 told through `hud._twinTabMoved`), and then stays; a rule the driver overrode stays overridden until its own state changes. The key source (`config.tabKey`, null) is the prototype's (level / mask / counter / any, rate limit, chained in front of the field's handler); one press = the next tab that exists (tab 2 only while a message is listed). Never locked.
2. **Settings** "Таба" (авто / 1..5) and "Не перемикати таби вище" (вимк. / 5 / 10 / 20 / 30 / 50 км/год, default 5) in `apps/twin_dial/app.json` (+ main menu item, `twin_tabs.js` in `shared`), `config.tabs`, `config.tabKey: null`. All applied **in place**: `hud.js` routes `tab`, `tabLock`, `centre` to `_twinTabsChanged`; the real-engine test counts layout builds (0 for every change).
3. **Tab bar (SPEC-R3 3)** in `design/gen_twin.py` (`TAB`, `tabs()`) and the regenerated `twin.json`: separators 780/848/1168/1237, rule [170,173]; tab 1 ink starts at x 636; range in Noto (`td_tabs` when B6's atlas is in the tree, else `td_tab`); tab 3 is one live widget painting icon + text as one group centred by the icon's ink with an ellipsis by width; **no dimmed icon** - state by variant (`td_phone_bars` / `td_phone_off` / plain `td_phone` until P9; `td_radio` / `td_media` / `td_proj`; the warning icon white, red (218,16,48 with the black floor) or amber only while a message shows and tab 2 is not selected; the nav icon stays the plain arrow until P12). Names missing from a build fall back to the plain icon.
4. **Fill:** B2 writes `hud.twinTab`; B1's `_twinBackSend` (colour table, ramp law, lightened rule, night) draws the cell. My own fill hooks were removed so the two do not collide. Verified on a scratch merge `twin-b/b2 + b6 + b1` (below).
5. **Bottom row follows the tab:** tokens `rowL1 .. rowR2u`; two lines on tab 1, one line (clock left, temperature right, baseline 656) elsewhere; the layout carries both, the choice is in place.
6. hud.js hooks (all `// twin_dial: tabs (B2)`): require, `TW_TAB_KEYS`, settings routing, `twinTabs.wire`, `_twinSync` (calls `update`), `_twinTabsOn`, `_twinTabsChanged`, a `_twinSync` in the 50 ms tick. `twin_tokens.js`: `page()` hook, titles, `callState`, row tokens, icon functions delegating to twin_tabs.

## Findings and decisions to confirm
- **"Icons 36 px" is ink height** (SF: ref 36 vs ours 29). B6 sized the tab slot as a 36 px box, whose ink is 28-33 px, i.e. no change. I used a **46 px box** (K2's mockups) on the centre line **y 147**; the spec's "centred at y 143" would stand 36 px of ink 1.5 px above the bar. B6 should set `slots.tab` to 46.
- The real engine at start has `twinCc.state = window` with severity null (blind keep-open): treated as **no message**, else tab 2 would show at every start (found by the real-engine test).
- Choices where the spec is silent: setting set to a number counts as the driver's choice (auto afterwards stays there until a rule fires); a new message after the driver left tab 2 pulls him back only at a new episode (message id changes inside one episode do not, B3 may add an id); message end under the lock returns to the tab before it (the prototype went to the pending rule's tab).
- Labels are Ukrainian as the brief says; the other settings are English. One-line change if the owner prefers English.
- `td_tabs` is picked automatically; **re-run `python3 design/gen_twin.py` after merging B6** (on the scratch merge it changes 7 lines).
- B1 changes `TW_RULE.tab`, TW_NIGHT etc. in hud.js; I removed my duplicates (my tests skip the cell-uniform checks when `hud.js` has no `twinTab`).
